# 长静音压缩：确认的产品规格

> **历史基线（已合并 main）**：本文记录 PR #1 阶段的原始行为。PR #2、PR #8、PR #10 已先后改变结果路径、M4A 裁剪方式和输出命名；现行行为见 [程序说明](../program-overview.md)，本文件仅用于追溯当时决策。

状态：**2026-11-23 已实现；M4A 实机裁剪与人工听感验收通过，真实 MP3/WAV 长停顿文件测试暂缓。** 详见 [验收记录](../Testing.md#2026-11-23-local-windows-acceptance-evidence-for-long-silence-trimming)。  
仓库：`chenjing2000/audioplayer`；基线为当前 `main`；功能分支：`feature/long-silence-trimming`。

## 目标及不变项

在英语音频播放器原有停顿导航功能之外，新增点击剪刀按钮压缩长静音的功能。输入与输出使用 WAV、MP3 或 AAC 编码的 M4A，输出扩展名与输入一致。不使用 FFmpeg，不改变原始音频；不改动基于 RMS/dBFS 的现有停顿检测数学定义。保持播放、暂停、停止、左右方向键和原有配置行为。

## 输入、界面与配置

1. 在设置（齿轮）窗口的四项原有参数之后追加 `允许静音时长 (s)`，标识为 `AllowedSilenceSeconds`（decimal），默认 `2.000`，小数部分至多三位。
2. 输入中仅允许 ASCII 数字 `0-9` 与一个英文小数点 `.`，禁止超过三位小数；键盘输入与粘贴一致。输入过程中允许空字符串和不完整小数；在失去焦点、按 Enter 或点击确定时完成验证。
3. 约束：`AllowedSilenceSeconds × 1000 >= MinimumSilenceMilliseconds`；最短停顿允许 50–5000ms，所以固定 0.1s 下限已取消。更改任一相关值，结束编辑时重新检查联动；错误留在原输入框，并沿用现有设置窗口的验证提示；不自动改值。Enter 在该输入框只验证，不关闭设置窗口。确定前检查全部参数。
4. 旧 `*.settings.json` 如缺少新字段，采用 `max(2.000, MinimumSilenceMilliseconds/1000)`；旧字段保留；显式无效的新字段不自动修复。只修改允许静音不会影响播放器已有停顿导航分析。
5. 主工具栏在设置按钮左侧添加剪刀图标按钮（`压缩长静音`）。从当前选中项（或聚焦的有效行）获取文件，而不是依赖点击按钮后仍有键盘焦点。未选择文件时显示非模态浮动提示。

## 检测和裁剪数学规则

静音检测继续复用 `SilenceDetector.Detect`。设静音区间为 `[s,e)`，持续时间 `D=e-s`，允许静音时间为 `T`：
- `D<=T`：原样保留。
- `D>T`：删除中央 `[s+T/2,e-T/2)`，首尾分别保留约 `T/2`。
- 各时间统一映射为原始音频的**采样帧索引**，总保留采样帧数按 `round(T × sampleRate)` 计算，前后差别不大于 1 帧。
- **先完整扫描所有静音，再计算全部删除区间**；不对原音频原地剪切。第二次顺序读取原始 PCM，只写未删除的采样帧，因此无后续片段坐标偏移问题，无需逆序剪切。
- 每个拼接点之前的最后最多 10ms 线性淡出至零、之后的最初最多 10ms 从零线性淡入。淡化仅发生在原本保留的静音中，不交叉叠加，不额外缩短音频；如两侧可用静音不足，缩短淡化长度。
- 初始或末尾的静音也按同样中央删除规则处理；即使没有人声也执行能量规则。算法没有 VAD 或背景音乐识别能力。

## 格式与产物

1. 文件列表增加 `.wav`、`.mp3`、`.m4a`，保留原有目录非递归扫描、自然排序、标签及错误回退。
2. 使用现有 NAudio 2.2.1 与 Windows Media Foundation 解码/编码，不引入 FFmpeg。对于受限系统编解码器，显示错误原因并不生成错误的正式文件。
3. WAV 输出可采用兼容 PCM；MP3 使用系统 MP3 编码器；M4A（AAC）使用 Media Foundation 的 MPEG-4/AAC 输出（编码临时文件使用 `.mp4` 容器扩展名，然后验证并以 `.m4a` 正式交付）。不承诺支持 ALAC 重新编码；不得仅改扩展名伪造格式。
4. 输出路径：源文件目录下的 `<stem>.lesssilence.<ext>`（例如 `lesson.lesssilence.mp3`）。已有正式目标文件时报告冲突，不覆盖；源文件始终不变。没有可压缩静音时，直接复制生成同名规则的新文件，不重编码。
5. 将唯一临时输出写在目标目录，完整完成并**重新解码检查**后再原子提交正式文件；失败/取消时清理本次临时文件；如果原文件或已有结果存在，应保证不受影响。
6. 考虑系统编码器尾部填充和 MP3/AAC 重编码损耗；重新解码后输出时长与预期长度应在合理容差内，不以文件字节大小等同于裁剪时间。

## 任务和反馈

- 裁剪是独立后台任务，使用点击时固定的路径与设置快照。只允许一个裁剪任务；期间禁止重复点击剪刀；不阻止正常播放/暂停/Seek，不更改播放器游标。
- 未选中、解码/编码失败、写入失败、目标冲突、完成等情况，均以非模态浮窗提示；进行中的提示不会被定时清除。
- 成功报告：完整输出路径、原始时长、输出时长、裁剪区间数、累计删除时长。当前文件夹未改变时，可按自然顺序加入新文件；不得在已经切换的文件夹中插入旧任务结果或自动替换播放对象。
- 关闭软件时安全取消或等待裁剪任务，清除临时文件，避免留下伪成功产物。

## 范围界限

不实现 VAD、背景音乐分离、字幕/WhisperX 时间戳重排、批量目录转换、新的参数窗口或额外的媒体依赖。不重构 MVVM，不改动旧测试/发布脚本职责。若 Windows Media Foundation 不支持用户特定 M4A，显示明确错误；需要 FFmpeg 由用户在后续单独授权。
