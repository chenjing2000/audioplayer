# AudioPlayer：统一通知与停顿结果持久化重构规格

状态：**2026-11-23 需求确认；已在功能分支编码并增加回归测试，待 Windows 实机验收；未合并 main**。基线：\`main\` 合并提交 \`c7b92ce\`。实现分支：\`feature/results-cache-toast-refactor\`。

本文件是本轮破坏性改造的权威规格；既有 [长静音压缩规格](Long-Silence-Trimming.md) 的 PCM 裁剪、淡化、格式/输出安全规则继续有效，但本文件对通知、结果存储、输出重名、参数精度与任务状态的规定优先。实施步骤见 [实施与验收方案](../guides/Results-Cache-Toast-Implementation.md)。

## 范围与不变项

- 保留加载音频后自动停顿分析，以支持左右方向键；**不新增**“停顿检测”按钮；不在选择文件夹时批量分析文件。
- 停顿检测与裁剪共用**一份** \`silence.json\` 静音区间结果。移除独立 \`cache/\` 设计，**取消 SHA-256**，不引入 SQLite、VAD、FFmpeg、通用任务队列或 MVVM 重构。
- 保留当前 PCM RMS/dBFS 静音检测、停顿中点导航、按原始采样帧裁剪、拼接点至多 10 ms 淡入淡出、系统编码器、原文件不变、临时输出验证及安全提交。
- 本次属于**破坏性升级**：不编写旧结果目录/JSON、旧缓存或旧参数精度的专门迁移/兼容逻辑。符合新规则的数据可读取；不符合时提示并重新生成/要求修正。**不主动删除**用户已有文件。

## 1. 唯一结果目录和 JSON

音频根目录为 \`Audio/\` 时，固定路径示意：

\`\`\`text
Audio/
  lesson.m4a
  lesson.lesssilence.m4a
  lesson.lesssilence (1).m4a
  results/
    lesson.m4a/silence.json
    lesson.lesssilence.m4a/silence.json
    lesson.lesssilence (1).m4a/silence.json
\`\`\`

- 目录名使用**完整音频文件名，包含扩展名**，以区分 \`lesson.mp3\` 与 \`lesson.m4a\`。
- 每个文件在 \`results/<完整文件名>/\` 下最多有**一份当前有效的** \`silence.json\`；新检测结果**覆盖更新原路径**，不生成 \`silence (1).json\`、版本复件、按 SHA 命名文件或第二套导航 JSON。
- 同一目录以后确有其他结果时才按功能命名新文件；本轮只创建 \`silence.json\`，不预建扩展架构。
- 两种消费者均以相同 \`silence.json\` 为依据：左右停顿导航计算区间中点，裁剪计算应删除的区间；不额外持久化中点、裁剪点、预计节省秒数等可由区间推导的字段。
- JSON 最小必要字段：\`schemaVersion\`、\`algorithmVersion\`、源文件完整文件名、\`sizeBytes\`、\`lastWriteTimeUtc\`、音频时长/采样率/声道数、三项检测参数（分析帧长度、最短停顿时长、静音阈值）及按先后顺序保存的 \`ranges\`（起止 \`TimeSpan.Ticks\`）。字段名/类型在实现测试中固定后不得随意漂移。\`NavigationToleranceMilliseconds\` 与 \`AllowedSilenceSeconds\` 不参与缓存有效性。
- 路径必须限制在选定音频所在文件夹的 \`results\` 下；只从 \`Path.GetFileName\` 推导结果目录，防止目录穿越。
- 文件为空、损坏、超出音频范围、起止逆序/重叠、负值、版本不兼容等均判为无效；无效结果不能用于裁剪或导航。检测成功时使用**同目录临时文件 + 安全替换**更新 JSON；失败/取消清理临时文件，保留原文件。临时文件不是永久复件。

### 有效性判断（不使用 SHA）

每次**加载音频结果**或**点击裁剪**时重新核对文件状态：

1. 文件名、字节长度 \`Length\`、UTC 最后修改时间 \`LastWriteTimeUtc\`；
2. 解码得到的实际时长、采样率、声道数（可利用当前已读取的音频元数据，避免额外全量扫描）；
3. 检测参数三元组、结果格式版本和检测算法版本、所有区间边界。

只有全部满足才能复用结果。检测开始与检测结束（正式写入前）、裁剪实际读写阶段也应复核源文件状态；发现变化时不得提交对应旧状态的结果/错误裁剪。按需重新检测，避免无穷循环；源文件反复变化时中止并提示。

**明确取舍：** 不计算 SHA，因而不能识别文件字节改变但文件大小、修改时间、音频基本信息完全相同的极端情况；不能宣称内容级完整性校验。正常本地文件管理下接受这一风险。

## 2. 自动检测、导航和裁剪

- 成功加载播放音频后，在**后台**检查当前 \`silence.json\`；有效则读入内存，不重新扫描 PCM；缺失/失效则执行原有 \`SilenceDetector.Detect\`，完成并验证后覆盖 \`silence.json\`，将区间装入当前播放会话内存。检测不阻止正常播放、暂停、停止、进度拖动、音频/文件夹切换。
- 检测过程中显示**持续可见的普通 Toast**：\`正在检测 <文件名> 的停顿，请等待检测完成。\`；成功后将同一条消息更新为简短报告（检测到的停顿数、可压缩段数、预计可减少时长）；失败时转为错误。有效缓存命中不显示虚假的“正在检测”。
- 左右方向键使用加载时已校验的内存区间与当前导航容差；连续按键**不重新访问 JSON、不计算 SHA、不扫描文件**。加载/参数变化后数据未就绪时导航暂不可用。若检测完成但写 JSON 失败，允许本次内存导航，显示警告，但不启用必须依赖持久化结果的裁剪。
- 当前选中列表文件是**裁剪目标**，不得误用另一条正在播放文件的结果。列表选中变化时可异步检查磁盘结果并更新按钮状态，不因此扫描其他文件；没有有效结果时按钮禁用，待该文件实际加载/自动检测成功才启用。
- 裁剪按钮只有在选中文件的有效 \`silence.json\` 已就绪、当前未分析/裁剪并且**存在可压缩静音区间**时启用；没有可压缩静音时禁用，避免生成无效副本。修改允许静音时长后重新计算“可压缩”状态，不重新检测。
- 用户点击裁剪时必须**再次验证当前文件基本信息和 \`silence.json\`**。有效时直接使用保存的 \`ranges\` 计算 \`PlanCuts\`，**不得在裁剪方法内部再次检测原音频**。若因外部文件变化导致失效，自动重新检测、覆盖结果，验证成功后继续当前裁剪请求；检测失败时终止，不能继续使用旧区间。文件再次变化时中止而非无限重试。
- 检测/裁剪彼此互斥、避免同一音频重复分析；正常播放控制尽量独立。每个异步操作绑定音频路径、参数快照、取消令牌和会话标识。音频/目录切换取消不再需要的自动检测，旧任务的完成回调不能更新新音频的导航区间、列表或错误的 Toast；裁剪以点击时源文件快照运行，切换目录后不得将旧输出插入新列表。关闭时取消/安全等待并清理临时文件。
- 仅调整三项检测参数（帧长度、最短停顿、阈值）时使旧结果失效，必要时自动重新检测当前播放音频；修改导航容差或允许静音时长不触发重新检测。

### 输出文件及输出结果

- 输出基本名仍为 \`<stem>.lesssilence.<ext>\`，如果已存在，按最小可用正整数依次尝试 \`<stem>.lesssilence (1).<ext>\`、\` (2)\`……；**左括号前保留一个 ASCII 空格**。已有输出一律不覆盖，最终提交时还必须抵御并发占名；原始文件不修改。
- 真正完成编码的新音频是**另一个独立文件**，应按其实际解码结果自动检测，写入自身 \`results/<新文件全名>/silence.json\`；不可把新的坐标覆盖到原音频的结果。原始音频存在有效结果时不重复检测原音频。
- 若输出仅是内容原样复制，可复用源静音区间生成输出的结果，不必重新扫描；本轮在“无可压缩区间”时默认不生成这样的无意义副本。
- 新音频已保存而后续结果生成失败：**保留音频**，提示“音频已保存，但停顿信息更新失败”，该文件下次加载时自动补齐。只有输出及结果流程均完成时才提示全部完成。

## 3. WPF Toast（删除 NotificationBar）

- **彻底删除**主窗口旧 \`NotificationBar\`、为其服务的底部独立布局行和显示/计时逻辑；所有用户可见的普通/警告/错误消息通过非模态 **WPF 悬浮 Toast** 展示，不引入 WebView2。
- 参照 ReadArticles 的通知行为：底部居中，不占布局高度；同时最多 3 条，超出按 FIFO 排队，已显示的较新消息置于上方；每条带关闭按钮；普通蓝、警告黄、错误红，前缀分别为 **“普通：”“警告：”“错误：”**；消息正文尽量不超过 3 行，不泄露堆栈/内部类名。
- 普通与警告短暂显示后淡出；鼠标悬停暂停计时；错误必须手动关闭；提供轻微入场/退场动画。**活动中的检测/裁剪任务 Toast 固定可见、占一个展示名额、不因 FIFO 饱和排队到不可见、不会自动到期**，状态变化复用同一消息。进行中可不允许关闭，以确保用户知晓后台任务。
- 设置窗口内也使用同种 Toast 提示字段错误；参数错误的红色边框保持到值修正。不能让主窗口 Toast 被设置模态窗口遮挡而造成无法阅读。

## 4. 设置窗口

- 窗口标题、齿轮按钮 ToolTip/AutomationProperties.Name 改为 **“设置”**。
- 五个 TextBox 共用一个圆角 \`ControlTemplate\`（建议 \`CornerRadius=6\`），沿用既有尺寸、居中、输入过滤和焦点行为；无效字段边框红色，改正后恢复。
- \`AllowedSilenceSeconds\` 默认 **\`2.0\` s**，最多一位小数。输入 \`2\`、\`2.\`、\`2.0\` 均有效，按 Enter、失焦或点击“确定”时标准化显示为 \`2.0\`；\`2.5\` 有效。编辑过程中允许空值或未完成小数；确认时空值、单独 \`.\` 或非法值必须标红，**“确定”不关闭窗口，也不保存**。\`2.35\`、\`2.00\`、负数等通过键入和粘贴一律限制。Enter 只验证，不关闭设置窗口；恢复默认清除红框/提示。
- 与最短停顿的动态约束保持：允许静音时长不能低于 \`MinimumSilenceMilliseconds/1000\`，一位小数下展示最小合法值为 \`ceil(MinimumSilenceMilliseconds/100) / 10\` 秒（例如 350 ms → 0.4 s）。只报错，不自动提高输入值。
- 内部 PCM 裁剪精度、取整与淡化不降级。旧配置不迁移、不静默修正，不主动删除；符合新字段和约束的数值可正常读取，旧值如 \`1.250\` 不满足新一位精度则按无效配置处理。

## 5. 音频列表

四列表头一律水平与垂直居中；“总时长”更名为 **“时长”**；时长列内容**右对齐**；所属专辑列内容**水平居中**。名称列内容仍左对齐，播放状态图标仍居中。保留原列宽、行高、隔行色、当前播放状态、长文本省略和 UI 行为。

## 6. 交付边界

- 不兼容旧 \`cache/\`、旧 \`results/<filename>.json\`、旧格式字段或三位小数输入；不自动扫描或删除旧文件。
- 不新增独立停顿检测按钮、批量转换、音频哈希、持久化历史复件、额外数据库、FFmpeg 依赖。
- 保留此前通过的 M4A 裁剪和听感验收证据；此重构尚未实现，不能沿用以前的通过记录声称新流程已测试通过。测试清单见 [实施方案](../guides/Results-Cache-Toast-Implementation.md) 与 [Testing](../Testing.md)。
