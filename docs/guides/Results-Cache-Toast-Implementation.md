# AudioPlayer：统一通知与结果缓存重构——实施和验收方案

**状态：2026-11-23 功能已实现，自动化回归与 Windows 实机 M4A、交互和听感验收通过；真实 MP3/WAV 长停顿测试按约定暂缓。** 权威要求：[Results-Cache-Toast-Refactor.md](../specs/Results-Cache-Toast-Refactor.md)。从已合并的 \`main@c7b92ce\` 在 \`feature/results-cache-toast-refactor\` 开发；不得未经授权合并 \`main\`。提交信息用英文、描述实际变化。

遵循第一性原理与最小必要设计。先删除失效的旧逻辑，再复用现有检测、PCM 裁剪、设置、WPF UI 与测试入口。不添加通用缓存框架、WebView2、SQLite、哈希校验或其他媒体依赖。

## 2. 分阶段实施（每阶段可独立审查）

### A. 结果数据与基础校验

1. 定义 \`results/<完整音频文件名>/silence.json\` 的唯一数据结构，按文件名定位，不使用 SHA，不创建 \`cache/\`。范围使用 \`TimeSpan.Ticks\`，文件元数据使用 \`Length\`、\`LastWriteTimeUtc\`、时长、采样率、声道数，版本号及三项检测设置。
2. 为读取的 JSON 验证版本、文件元数据、检测参数以及范围排序、不重叠、边界有效性；检测成功采用同目录临时文件后替换的方式覆盖固定 JSON 路径，失败不破坏旧文件；无旧格式迁移/删除。
3. 复用现有 \`SilenceDetector.Detect\` 的返回结果；它同时驱动导航和 \`SilenceTrimmer.PlanCuts\`。只有发生参数/源文件变更才重跑。写入失败时保留本次内存导航结果，但磁盘依赖的裁剪不可用。
4. 检测前/后验证文件元数据，明确处理修改中的文件和同名目录写入失败。避免把未经验证的 JSON 直接用于 PCM 裁剪。

### B. 自动分析与任务生命周期

1. 保留音频加载时的自动停顿分析入口：先在后台确认结果是否有效；有效读入内存，跳过 PCM 扫描；无效/缺失进入后台检测并写盘。不要因选择文件夹而对全目录排队分析。
2. 使用每次加载/设置变更的路径、参数快照、任务标识和 \`CancellationTokenSource\`。切换音频取消旧自动检测；关闭时取消、等待并释放。旧回调不得覆盖新 \`loadedTrack\` 的 \`ranges\`、\`analysisReady\` 或通知。
3. 保留正常播放、暂停、停止、Seek、切换文件/文件夹；不要用全局 \`analyzing\` 阻止无关操作。当前会话数据未就绪时左右导航暂不可用；就绪后按键从内存查找中点，不重新打开 JSON。
4. 同步变更当前选中项的裁剪可用性：选中项可异步校验**已有**结果，但未加载且没有缓存时不主动扫描；结果不匹配或无可压缩区间则禁用。将播放目标、选中项及正在裁剪的来源区分清楚。

### C. 裁剪与输出更新

1. 点击裁剪时固定源路径与设置，**重新校验**元数据和 JSON。有效则将 \`ranges\` 传入裁剪（不重新调用 \`Detect\`）；失效则在同一请求中自动重新检测并安全覆盖结果后继续；若再次变化/检测失败则停止。
2. 有候选可压缩区间时按先前已验收的 PCM 帧级 \`PlanCuts\`/fade/编码流程导出。输出先尝试 \`stem.lesssilence.ext\`，随后按最小可用 \`stem.lesssilence (1).ext\`、\` (2)\`……；最终提交仍禁止覆盖，遇到占名竞争尝试下一序号。
3. 对**实际重新编码**的输出文件进行独立停顿检测，在 \`results/<输出全文件名>/silence.json\` 生成唯一结果；如确为字节复制则可重用原结果。源音频及其结果不改。
4. 输出音频已经保存却在后续结果生成/写入时出错，要保留音频并发出清晰警告。只在本次裁剪及输出结果更新均结束后释放裁剪互斥状态。切换文件夹后不得污染新列表。

### D. 通知与 UI

1. 改为纯 WPF Toast 覆盖层，删除旧 \`NotificationBar\` 和旧定时器。普通/警告/错误的颜色、前缀与最多 3 条 FIFO 参考 ReadArticles；自动消失、悬停暂停、错误手动关闭、手动关闭按钮、淡入淡出。屏幕窄时保证文本不超过约三行。
2. 长时间的分析和裁剪使用**始终可见的一条任务 Toast**，先显示“正在检测……请等待”，完成后原位更新为结果；错误改为错误消息；任务运行期间不被其他消息挤出视野。缓存命中不展示假的检测进度。
3. 设置模态窗口使用本窗口内同样风格的 Toast，异常文本避免泄露调用栈；字段错误同时保留红框直到修正。
4. 五个输入框采用一个共享圆角样式，窗口/齿轮名称为“设置”；调整 DataGrid 四列标题居中、时长值右对齐、专辑值居中；保持现有布局/宽高及行行为。

### E. 最终整理与交付

- 删除本轮遗留的旧通知/旧分析复扫/旧结果文件假设和失效测试；尽可能修改现有实现而不是增加并行代码。
- 统一功能、配置、使用说明和测试说明中对新规则的描述。旧版本验收记录保留历史真实性，不挪用来宣称新功能已通过。
- 本分支完成测试与 Windows 实机验收后再提交合并申请；未获明确授权不合并主分支。

## 3. 必须覆盖的回归测试

### JSON/有效性与生命周期

- 首次加载无结果 → 自动检测 → 写固定 \`silence.json\`；再次加载有效 → 不调用 PCM 检测；左右方向键重复跳转仅访问内存。
- 改变文件大小/最后修改时间/有效检测参数、损坏 JSON、范围超出音频时判为失效；导航容差、允许静音时长改变不造成多余扫描；取消 SHA 后**不声称**识别相同元数据下内容变化。
- 多次检测覆盖同一路径，永不生成 \` (1)\` JSON 或 \`cache/\`；只保留一份权威结果；临时写入失败时旧文件完整且新结果不误标记为有效。
- 检测中切换文件/文件夹、改变参数、关闭窗口、外部修改源音频；取消旧任务、结果不串台，正常播放操作可用。
- 文件名仅扩展名不同、文件名带空格/中文/括号、读取权限不足、目录不可写、文件被其他程序占用。

### 裁剪与音频安全

- 命中有效结果 → 绝不重复检测原始音频；点击时发现失效 → 自动重新检测成功后继续；检测失败/源文件再次变化 → 中止且源数据不变。
- 从缓存结果推导的裁剪区间，与原 PCM 检测后直接 \`PlanCuts\` 的输出一致；所有原有 10ms fade、边界、声道、时长验证继续通过。
- \`stem.lesssilence.ext\` 已存在时生成 \` (1)\`、\` (2)\`，中间编号空缺优先填最小可用号；竞态占名不能覆盖已有结果。
- 没有可压缩区间时禁用裁剪，不生成无意义副本；只修改允许静音时长会重新计算此按钮的可用性。
- 输出音频和输入音频各自对应一个 \`results/<全文件名>/silence.json\`；输出音频实际重新编码后重新检测；输出音频保存成功而其结果失败时应保留音频并明确警告。

### WPF/设置/列表

- 三类 Toast 前缀、颜色、最大 3 条 FIFO、鼠标悬停、超长文字、错误持久、手动关闭及任务 Toast 常驻；删除旧 \`NotificationBar\`，不出现模态消息阻塞播放。
- \`2\`、\`2.\`、\`2.0\` 都规范显示 \`2.0\`；\`2.35\`、\`2.00\` 禁止键入/粘贴；空值点确定红框且不关闭、不保存；修改后恢复；动态下限 350ms→0.4s，Enter 不关闭。
- 五个输入框圆角、设置标题、四个表头水平/垂直居中、“时长”列右对齐、“所属专辑”值居中、播放状态/行色/焦点行为不回归。
