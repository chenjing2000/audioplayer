# 长静音压缩：实施与验收方案

对应规格：[Long-Silence-Trimming.md](../specs/Long-Silence-Trimming.md)。
规范来源：`chenjing2000/windowsappplaybook` 的设计框架、可复用模式、UI 指南和验证形态。

## 分支与授权

全部代码、规格和测试改动只在 `feature/long-silence-trimming` 分支进行；不得合并或直接写 `main`。Git 提交信息英文，描述实际变化。功能开发与数据安全已获本轮授权。真实 Windows 验收若不可运行须注明限制，不可声称通过。

## 最小实现分层

1. **检测层**：继续复用 `SilenceDetector.cs` 和 `SilenceRange.cs`，仅按需增加取消支持；不混入输出编码逻辑。
2. **核心裁剪层**：在 `EnglishAudioPlayer/SilenceTrimmer.cs` 计算采样帧级删除区间、逐块流式读取与跳过、10ms 淡化、按扩展名编码、验证及临时文件安全提交。与播放输出设备和 UI 脱耦。
3. **配置层**：在 `SilenceSettings.cs` 添加 decimal 属性并校验其与最短停顿时长的关系；`SettingsStore.cs` 对缺失字段的旧 JSON 做安全默认处理；设置窗口 XAML/后台增加文本输入与联动验证。
4. **列表/UI 层**：`AudioLibrary.cs` 扩展文件类型；`MainWindow.xaml` 新增剪刀按钮与提示视觉；`MainWindow.xaml.cs` 管理裁剪任务、提示、完成后列表更新以及关闭安全释放；`ui/Icons.xaml` 新增剪刀图标。原有音频播放控制独立不变。
5. **规范接入**：简明 `AGENTS.md` 和 `docs/project-contract.md` 明确当前项目真实位置、依赖、测试入口和已有配置路径例外；更新文档索引与配置、测试说明，避免新增重复规格。

## 实施顺序

A. 从 `main` 创建功能分支并同步规格与文档。  
B. 实现核心采样索引算法及 WAV 测试，无需 WPF/实际音频设备。  
C. 实现配置联动、UI 和任务生命周期。  
D. 集成 MP3、AAC/M4A 编码并做输出复检，不能用代码推断替代实测。  
E. 增补核心/集成用例，运行原有测试、构建、UI、真实格式导出、实际发布验证。

## 必须覆盖的边界

- 静音持续时间小于、等于、大于允许值；单个和多个区间；首尾静音；完全静音；无静音；不完整最后一帧；有损编码器的时长容差。
- 双声道不交叉；非整数采样帧边界；允许时长小数三位；淡出淡入不侵入语音；输出帧数等于原始帧数减去删除帧数。
- 动态下限：50ms→0.050s，300ms→0.300s，5000ms→5.000s；旧 JSON 缺新字段且旧最短时长大于 2000ms；显式无效配置；失焦、Enter、粘贴输入。
- 播放器不受后台裁剪影响；点击剪刀时焦点从列表转移仍使用所选文件；无选择有提示；任务中重复点击被拒绝；关闭/切目录后旧任务不得污染界面。
- 错误路径：无法解码、不支持编码、只读目录、目标已有、取消、源文件损坏、临时文件检查失败；原始文件及已有输出不能受到影响。
- WAV、MP3、AAC/M4A 通过真实 Windows 媒体文件回放和重新解码检查，不支持时明确记录和提示。缺真实测试素材时按跳过处理。

## 验证与交付要求

既有入口：`tools/Test.ps1 -Suite Core|UI|Full`、`tools/Publish.ps1` 与 `tools/Test-PublishedApp.ps1`。额外核心用例写入现有测试工程，尽量用合成 PCM 而不是随 Git 提交真实音频。分别汇报静态审查、编译、自动化测试、Windows 实机与格式测试的真实状态。

发布保持框架依赖型 .NET 10 便携式单文件，并保护用户音频和现有 EXE 同目录的配置文件。若后续编码限制迫使运行形态改变，先单独说明，不能静默引入 FFmpeg。
